## 一、模板是什么

这个 skill 不预设资料类型。每做一类新资料，就在项目里搭一套生成工具；做完把它收进模板库，下次遇到相近的资料直接套用。

```
templates/<模板名>/
  模板说明.md     适用于什么资料、有哪些版本、标记写法、效果图、踩过的坑
  build.py        内容稿 → 成品 Word（必有）
  样式.json       主题、字号、版本等参数
  封面.html       可选
  样章图/         2–4 张效果图，方案阶段给用户看
```

起步模板：`考点答题模板`、`英语语法手册`、`知识手册_背诵默写`、`手写笔记`。

## 二、方案阶段：挑模板和主题

```bash
$RUN template list          # 每个模板适用于什么、有哪些版本
$RUN theme list             # 每套主题的颜色、风格、适合的资料
```

- 看用户的参考和需求单，选**最相近**的模板；版式差别大的，选结构最近的改
- 主题照参考的风格选（视觉规范第七节）；都不合适就新建一套
- 写进方案的「版式方向」

## 三、搭项目工具

```bash
$RUN template use <模板名> <项目>      # 把模板复制进 <项目>/2_样张/排版/
```

- 在 `<项目>/2_样张/排版/` 里改：`样式.json` 换主题和参数；`build.py` 按参考加组件；`项目规范.md` 记这个项目的标记写法和约定
- 没有相近模板时：复制最简单的一个，删掉用不上的组件，用第五节的积木加新组件
- 标题层级和参考不一样时，直接改项目 build.py 里的 `chapter` / `section` / `kp` 这几个函数；要四层（章 → 课 → 节 → 考点）的，照 `templates/考点表格_背诵默写/build.py` 的 `kaodian`
- 新加的组件和标记**同时写进 `2_样张/排版/项目规范.md`**，沉淀模板时它就是新模板的标记说明
- **改项目里的副本，不改模板本身**

## 四、build.py 的约定

```bash
python3 <项目>/2_样张/排版/build.py <项目> [--only 版本] [--pdf]
```

- 读 `<项目>/2_样张/内容稿.md`（或 `内容稿_分章/`），在 `<项目>/3_成品/` 生成每个版本的 .docx
- 带 `--pdf` 时：用 `export_pdf.export()` 导出 PDF，按 PDF 找页码回填目录，再导一次
- 打印每个版本的文件名；出错直接报错退出，不出半套文件
- 一份内容稿出所有版本（背诵 / 默写、学生 / 答案），版本差别只在 build 里处理

`$RUN build <项目>` 会先跑它，再统一做：拼封面 → 出预览图 → gates → 清属性 → audit → 交付说明。

## 五、docx_kit 常用积木

`scripts/docx_kit.py` 是所有 Word 模板共用的底层积木（文件开头有完整说明）。**新建模板时，先复制最相近的模板的 build.py 改**（例如 `templates/知识手册_背诵默写/build.py` 里的 `Builder` 已经实现了章节标题、条目、三线表、图文排版、信息框、目录回填、背诵 / 默写挖空），只有缺的组件才用积木新写：

```python
import docx_kit as K
S = K.load_theme(HERE / "样式.json")        # 样式.json 里写 "主题": "考点表格风" 就先套主题配色
F = K.FONTS                                 # 按系统选好的字体：serif / hei / kai / latin / title
K.setup_page(doc, margins=(上, 下, 左, 右))   # A4 页面 + 正文默认字体
K.set_font(run, F["serif"], F["latin"], 10.5, True, S["colors"]["main"])
K.para_fmt(p, before=0, after=3, line=18, left=0.5, first=-0.5)
K.borders(tbl, {"top": (8, 主色), "bottom": (8, 主色), "insideH": (2, 细线色)})   # 三线表
K.shd(cell._tc, 浅底色)                      # 表头、信息框底纹
K.field(p, "PAGE", ...)                      # 页码
pdf, engine = K.export_best(docx)            # 优先 Word 导出，失败退回 LibreOffice
pages = K.find_pages(pdf, toc_entries)       # 找每个标题在第几页，回填目录
K.attach_cover(cover_pdf, pdf)               # 封面拼到最前面
```

- 字体按系统自动换（Mac / Windows）；颜色只从主题和样式.json 取，不随手写色值
- 行内标记约定：`**加粗**`、`{{关键词}}`（背诵版红字加粗下划线、默写版同宽挖空）
- 背诵 / 默写、学生 / 答案这类多版本：同一个 Builder 带 `mode` 参数各跑一遍，不复制内容

## 六、沉淀成模板（第 ⑩ 步）

项目交付后，用户没有反对的话：

```bash
$RUN template save <项目> <模板名>
```

- 把 `<项目>/2_样张/排版/` 里的 build.py、样式.json、项目规范.md、封面 和 2–4 张预览图收进 `templates/<模板名>/`
- 自动生成《模板说明.md》初稿，再补全：适用于什么资料和用户群、版本、标记写法、样章定稿标准、踩过的坑
- 模板里**不能**有这个项目的具体内容、原作者信息、素材路径
- 新主题同样存进 `assets/主题/`（`$RUN theme save`）

## 七、偏好文件

```bash
$RUN prefs            # 看当前偏好；第一次用时一次问完、存下来
```

- 位置：`<skill>/../偏好.md`（跟着整个工作文件夹走）；项目里的 `<项目>/偏好.md` 优先
- 记：常做的用户群、默认交付形式、默认改写档位、喜欢 / 不喜欢的样式、默认主题、是否上传知识库
- **开工第一件事读偏好**，用它预填需求单；用户这次说的和偏好冲突时，以这次为准，问一句要不要更新偏好
- 还没有偏好文件时：用户在线就按 `prefs` 打印的问题一次问完、写进 `<skill>/../偏好.md`；用户不在线就先不建，需求单里用推荐默认值并标「默认」
