## 一、脚本闸门

```bash
$RUN check <项目>     # 内容稿：出处、【缺】、机器味、中文排版、原作者信息、题答对应
$RUN gates <项目>     # 成品：填充率、版本页数一致、目录页码、重开校验、出处核对
$RUN audit <项目>     # 交付：成品里的原作者信息、文件属性（会先自动清属性）
```

`build` 结束时自动跑 gates 和 audit：出成品时报告在 `3_成品/检查/`；出样章（`build --sample`）时报告是 `2_样张/样章闸门报告.md`、`样章检查报告.md`。

| 闸门 | 查什么 | 拦截（不通过不能进确认点） | 警告（逐条判断，结论写进进度记录） |
|---|---|---|---|
| check | 内容稿 | 无出处的块、【缺】（除非用户同意保留）、机器味 error、原作者信息 error、题答条数不符 | 机器味 warn、平台名 |
| gates · 填充率 | 每页内容占版心比例 | — | 正文页 <80%（章末页不限） |
| gates · 版本一致 | 背诵 / 默写、学生 / 答案各版本 | 页数不一致 | — |
| gates · 目录 | 目录页码 vs 正文（会自动算封面带来的整体偏移） | — | 个别标题页码对不上 |
| gates · 重开校验 | 用 Word 库重新打开每个 .docx、PDF 能读页数 | 打不开 | — |
| gates · 出处核对 | 出处页里能不能找到这一块的关键词和数字 | — | 找不到的逐条人工核 |
| audit | 成品里的原作者信息、文件属性 | error | 平台名等 warn |
| 手写笔记 | 字体加载、内容超出 | 字体没加载、超出 | 强调过多、组件过多 |

**填充率不够怎么改**（按顺序试）：把下一块内容挪上来 → 允许大框、长表跨页 → 表格格子里的 ①②③ 分成多行让表变高 → 补素材里有的细节（易错汇总、对比、快问快答）。**不放大字号、不加装饰、不编内容凑**；标题加整块内容被一起推到下一页造成的空白，先试前两种。

**闸门不过就改了重跑，最多三轮**；三轮还不过，停下来在进度记录里写清卡在哪，告诉用户。

## 二、人工逐页清单（看预览图，逐条打勾写进进度记录）

用 Read 看 `2_样张/预览/<文件名>/总览-*.png`，有疑问的页看单页。

1. 层级一眼看清，没有连续 3 段纯文字
2. 内容丰富，正文页 ≥80%，没有大片空白（章末页不限）
3. 标题没落页尾；例题和答案、图和说明没分家
4. 图清楚，没有页眉水印残留，图注对，放在讲它的文字旁边
5. 表格整齐、撑满版心、没被拆坏
6. 关键词加粗红字都在，没有满屏标红
7. 没有视觉规范第九节的禁区
8. 随机抽 5 处内容回素材核，全对
9. 封面、目录、内页风格统一；目录页码对

## 三、原作者信息清零（红线）

成品是我们的产品，原素材的个人和品牌印记要去干净。**任何交付文件里都不能有**：正文、封面、页眉页脚、图片、文件名、文件属性。

- **要清掉的**：原作者姓名、笔名、网名、签名、头像；「××老师」「××学长」；个人、工作室、机构、网店名；专属系列名和原商品名；水印、版权声明、二维码；联系方式和引流话术（微信 / VX、QQ 群、公众号、小红书号、抖音、店铺、「给个好评」「无偿答疑」）；暴露原作者身份的口癖和自述（「友友们」「我花 10 小时整理」「我第三次备考」）
- **要保留的**：有教学意义的人名（课文作者、题干人物、名言出处、历史人物）；正常教学内容里的平台名（「公众号提建议」）
- **怎么做**：
  1. 入库后读 `1_规划/原作者信息.txt` 候选区，加上看图发现的署名、水印，把确认的名字和变体写进「屏蔽词」区，一行一个
  2. 写内容稿时就改掉；署名删掉即可，不换成别人的名字
  3. `check`、手写笔记检查、`audit` 按屏蔽词 + 引流词查，error 必须清零
  4. 嵌图只能看图核对：带标记的图换成干净的裁切或重画，不要只盖一层色块
  5. 交付说明、给用户的回复里用素材编号（S01）或中性名称

## 四、文件命名

- `<资料名>（<版本>）.docx / .pdf`，如「八上生物学知识手册（默写版）.pdf」
- 不带日期、「最终版」「v2」；资料名里不出现原作者和原系列名

## 五、交付汇报模板（确认点三，照填）

```
已完成：《<资料名>》
- 文件：<版本1> N 页、<版本2> N 页（完整路径）
- 内容来自：S01 课本、S02……（编号或中性名称）
- 整合升级做了什么：……（3–5 条，如「三份资料合成一章」「新增 12 张对比表」）
- 还缺：【缺】……（没有写「无」）
- 检查：出处 / 机器味 / 原作者信息 / 填充率 / 版本一致 全部通过
- 需要你做的：在 Word 里过一遍、导出正式 PDF（如果是 LibreOffice 预览版）……
- 上传：已传 / 未配置 / 不需要
```

同时写《交付说明.md》（build 自动生成后补充上面的内容）。

## 六、上传到知识库（可选，第 ⑪ 步）

需求单里用户要了才做；**两种都要用户先手动配置好**（安装配置.md 第六节），没配置就跳过，交付汇报里写「未配置」。

| 目标 | 怎么传 |
|---|---|
| 飞书知识库 | 用 lark-cli（飞书 CLI）：先按 lark-drive 的方式把 PDF / Word 上传到云空间或导入为文档，再按 lark-wiki 的方式放进指定知识库节点；知识库和节点由用户指定 |
| ima 知识库 | 用户接好 ima 的 MCP 后，调用它的上传工具，把成品 PDF 传到用户指定的知识库 |

上传前再跑一次 audit；上传后把链接写进交付说明。
