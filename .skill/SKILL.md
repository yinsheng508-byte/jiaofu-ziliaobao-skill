# 教辅资料包

## 这个 skill 做什么

**输入**：用户提供的①参考资料（同行成品、截图、讲义、真题）②电子课本 / 教材 ③用户自己整理的资料。
**产出**：用 AI 的整合能力**优化升级**成一份新的资料产品，比任何一份原素材都更清晰（结构、层次、重点）、更完整（几份互相补全）、更丰富（例子、对比、易错、记忆方法）。
**做成什么样**不预设：在方案阶段按用户的参考和需求定，做的过程中搭这个项目的生成工具，做完沉淀成模板，下次直接套。

## 八条红线（任何时候都不能违反）

1. **知识不编**：知识点、数据、年代、定义、题目、答案、图都来自素材或课本；没有就标【缺】问用户。结构、表述、归纳方式可以原创
2. **每块有出处**：内容稿里每一块标〔S03 p12〕，交付前不能有无出处的块
3. **不留原作者信息**：原素材的作者名、网名、机构 / 店铺名、系列品牌、水印、二维码、联系方式、引流话术，任何交付文件里都不能有（正文、封面、页眉页脚、图片、文件名、文件属性）
4. **像老师在 Word 里精调**：用 Word 原生的样式、目录、表格、页眉页脚排版，先 Word 后 PDF；不做网页卡片感，不用代码直接排 PDF（手写风笔记例外）
5. **内容要丰富**：素材里有的构件（例子、易错、对比、口诀、图）都要收；正文页填充率 ≥80%（章末页不限）
6. **没有 AI 腔**：不用「首先 / 其次 / 综上 / 值得注意的是 / 即可」这类词，像老师讲课
7. **闸门不过不往下走**：check / gates / audit 的拦截项必须清零
8. **该问的问，不该问的不问**：命中「必须问」清单才停下来问，一次最多 3 个问题、带选项

## 三个阶段，三个确认点

每个项目分三个阶段，各有一个文件夹；每个阶段结束停一次，等用户确认：

| 阶段 | 文件夹 | 做什么 | 确认点：交给用户什么 |
|---|---|---|---|
| **一、出规划** | `1_规划/` | 需求单 → 素材入库 → 素材覆盖表 → 方案 | 《素材覆盖表》《方案》 |
| **二、出样张** | `2_样张/` | 搭排版工具 → 写第一章内容稿 → 排出第一章样章 | `2_样张/样章/` 里的第一章成品 + 预览图 + 样章汇报 |
| **三、出成品** | `3_成品/` | 照样章标准铺开全书 → 全书质检 → 交付 | `3_成品/` 里的全部 Word / PDF + 交付汇报 |

- 样章确认后，用户的调整写进「样章定稿标准」，其余章节照做，**阶段三中间不再停**
- 只有会推翻方案的大问题才中途额外停（缺整章素材、页数超一倍、教材版本对不上）；用户说「不用看样章」就跳过确认点二
- 用户不在线（自动运行）时：要问的写进 `1_规划/提问记录.md`，按推荐选项继续，到确认点照样停下汇报

## 路径与命令

- `<skill>` = 本文件所在目录；命令统一入口 `python3 <skill>/scripts/run.py <子命令>`（Windows 用 `python`），下文记作 `$RUN`
- 用户放资料：`<skill>/../输入资料/<资料包名称>/`，里面三个子文件夹（模板和说明在 `输入资料/说明.md`）：
  - `1_教材课本/`：教材或电子课本，用来核对内容
  - `2_对标资料/`：收集的对标资料、用户自己整理的资料，内容来源
  - `3_参考版式/`：想要的排版样子（图片或文档），只看版式不取内容
- 项目：`<skill>/../输出项目/<YYYY-MM-DD>_<资料包名称>/`；原资料不移动
- 命令都接**项目文件夹**（不是阶段子文件夹），脚本自己找对应的子文件夹
- 第一次用、环境报错：按 [references/安装配置.md](references/安装配置.md) 配好

## 项目文件夹

```
输出项目/<日期>_<资料包名称>/
  进度记录.md                   做到哪、用户定过的事、下一步（换对话时先读它）
  1_规划/
    需求单.md                   给谁用、做什么用、交付形式、版本、改写档位
    素材/                       每份素材抽出的文字和页图（S01、S02……）；原资料不移动
    素材清单.md                 编号、类型、页数、是否已抽字 / 已识别
    原作者信息.txt              原作者名、店铺名、水印的屏蔽词，成品里会全部清掉
    素材覆盖表.md               每份覆盖什么、哪份最全、各自独有什么
    参考/                       用户给的参考截图
    方案.md                     目录、每节用哪份素材、预计页数、版式风格、缺什么   → 确认点一
    提问记录.md                 用户不在线时记下的问题和推荐选项
  2_样张/
    内容稿.md                   资料包的全部文字，每块标出处（出处只在这里，成品里自动删掉）
    检查报告.md                 内容稿检查结果（出处、AI 腔、原作者信息）
    排版/                       这份资料包的排版工具（从模板复制来改）
    封面/  预览/                封面；每页预览图
    样章/                       第一章成品（build --sample 出的）
    样章汇报.md                                                               → 确认点二
  3_成品/
    <资料包名称>（版本）.docx / .pdf   交付物，用户重点看这一层
    交付说明.md                 每个文件几页、内容来自哪些素材、还缺什么          → 确认点三
    检查/  闸门报告.md  交付检查报告.md
```

## 阶段一：出规划（`1_规划/`）

### ⓪ 开工

`$RUN prefs` 读偏好（还没有偏好、用户在线时一次问完存下来）；接着做的项目先读《进度记录.md》。环境没配过先 `$RUN doctor`。

### ① 需求单

读 [references/需求与方案.md](references/需求与方案.md) 第一到四节。按需求单问清：给谁用、做什么用、参考是什么、交付形式、版本、改写档位；拆解用户给的参考（截图存进 `1_规划/参考/`）。
**完成**：《需求单.md》填完，参考拆解写好。

### ② 入库

读 [references/取材规范.md](references/取材规范.md)。

```bash
$RUN new 输入资料/<资料包名称> --title <资料包名称>     # 建项目 + 入库；追加：$RUN add <项目> <资料>...
```

脚本按三个子文件夹自动分：课本先编号（S01 起），再是对标资料，《素材清单》的类型里标「（课本）」「（对标资料）」；参考版式只拷进 `1_规划/参考/`，不入库。用户没分文件夹时，整个文件夹都当对标资料。缺课本、缺参考版式时脚本会提示，按提示处理，不用停下来问。

扫描件先 OCR 再看图校对；没有电子课本按取材规范第四节处理；读 `原作者信息.txt` 候选区，把确认的名字写进「屏蔽词」区。
**完成**：每份素材都是「已抽字」或「已 OCR 已校对」；屏蔽词已填。

### ③ 素材覆盖表

逐份读完全部素材，填《素材覆盖表.md》：每份覆盖什么、质量怎样、哪份最完整、各自独有什么。
**完成**：每份一行，每个知识单元标出主素材。

### ④ 方案 → 确认点一

读 需求与方案.md 第五节、[references/视觉规范.md](references/视觉规范.md) 第七节、[references/模板指南.md](references/模板指南.md) 第二节。

```bash
$RUN template list        # 有没有相近的模板
$RUN theme list           # 选主题
```

这一步**只读**候选模板的《模板说明.md》和样章图来挑，不复制。按方案模板写《方案.md》：目录（每节用哪份素材、预计页数）、版本、版式方向（风格、主题、模板）、改写档位、缺口、原作者信息、待定的事。
**完成**：方案照模板填满 → 交给用户，**等确认**。

## 阶段二：出样张（`2_样张/`）

### ⑤ 搭工具、写第一章

读 [references/内容规范.md](references/内容规范.md)、[references/文风规范.md](references/文风规范.md)、模板指南.md 第三到五节，以及所用模板的《模板说明.md》。

```bash
$RUN template use <模板名> <项目>     # 复制进 2_样张/排版/，按方案改样式和组件
$RUN check <项目>                     # 写完第一章就查
```

按模板的标记写《内容稿.md》，**先只写第一章**：整合升级（重组、补全、重新讲清楚、做归纳表）、每块标出处、关键词标 `{{}}`。写完对照内容规范第八节自查。
**完成**：第一章 check 无 error；自查清单打勾。

### ⑥ 第一章样章 → 确认点二

读 视觉规范.md、[references/质检与交付.md](references/质检与交付.md) 第一、二节。

```bash
$RUN build <项目> --sample     # 出到 2_样张/样章/：Word → PDF → 封面 → 预览图 → 闸门 → 原作者信息检查
```

用 Read 逐页看 `2_样张/预览/` 的图，按人工清单改到干净（最多三轮）。
**完成**：拦截项清零、人工清单打勾 → 按需求与方案.md 第七节写《样章汇报.md》，**等确认**；用户的调整写进进度记录「样章定稿标准」。

## 阶段三：出成品（`3_成品/`）

### ⑦ 铺开其余章节

照样章定稿标准一章一章写进内容稿、check、看预览（中途想看效果用 `--sample`），**中间不停**；每章更新进度记录。

### ⑧ 出成品、质检

```bash
$RUN build <项目>              # 全书出到 3_成品/：Word → PDF → 封面 → 预览 → 闸门 → 清属性 + 原作者信息检查 → 交付说明
```

**完成**：`3_成品/检查/` 里两份报告的拦截项清零；警告逐条判断写进进度记录；原作者信息清零。

### ⑨ 交付 → 确认点三

按 质检与交付.md 第五节的模板回复用户，补全 `3_成品/交付说明.md`。

### ⑩ 沉淀模板

用户没反对就 `$RUN template save <项目> <模板名>`，补全《模板说明.md》；新主题 `$RUN theme save <项目> <主题名>`；通用的经验回写进 references（写规则和原因，不记流水账）。

### ⑪ 上传（可选）

需求单里要了、且用户配置过，才按 质检与交付.md 第六节传飞书知识库 / ima 知识库。用户要上架的，接着做商品主图（下面「商品主图」一节）。

## 手写笔记（/手写笔记）

用户要「手写笔记」「手写风」「能打印的笔记」时，阶段一照做；手写稿放 `2_样张/手写笔记/`，成品出到 `3_成品/手写笔记/`。动手前读 [templates/手写笔记/手写笔记规范.md](templates/手写笔记/手写笔记规范.md)。三个确认点照旧。

## 商品主图 / 详情图（/商品主图、/主图）

资料包交付后要上架，或用户直接说「做商品主图」时：读 [templates/商品主图/模板说明.md](templates/商品主图/模板说明.md)，固定出 3 张 3:4 图（商品主图、购前须知、卖点展示）。
- 资料包项目输出到 `3_成品/主图/`，主图里的资料页取 `3_成品/` 里的成品；只给主题的输出到 `输出项目/<日期>_<产品主题>_主图/`
- **店铺名每次由用户提供，不写进任何文件**（只写在这一次的 spec.json）；主图配色从 `assets/主图模板/` 选（`$RUN mainimg templates`）

```bash
$RUN mainimg pages <资料.pdf> <输出目录>/assets 6     # 资料页转图
$RUN mainimg <输出目录>/spec.json                     # 出 01–03.png
```

## 长项目接续

- 《进度记录.md》（项目根目录）每步更新：需求单摘要、用户已定的事、确认点状态、样章定稿标准、每章状态和闸门结果、下一步
- 要压缩上下文前先写进度；换会话后**第一件事读它**，再读 `1_规划/方案.md` 和素材覆盖表
- 用户定过的事不再问
- 老项目（文件平铺在根目录、没有 1_规划/ 的）脚本自动识别，照旧能跑
